# OctoAcme Project Management Docs

This directory centralizes OctoAcme's project management process documents and provides a brief overview of how we run projects. Use the linked documents for full guidance, checklists, and templates.

## Overview

OctoAcme follows a lightweight, iterative lifecycle from Initiation → Planning → Execution → Release → Retrospective. Initiation captures the problem, objectives, stakeholders, and success metrics in a Project One-pager to gate planning. Planning turns approved initiatives into a prioritized, estimated backlog, defines the Definition of Done, maps milestones and release plans, and identifies key dependencies and risks.

## Workflows & Quality

Execution uses a project board workflow (Backlog → Ready → In Progress → In Review → QA → Done), timeboxed sprint planning, and a pull request process that favors small PRs with linked issues and clear acceptance criteria. CI runs tests and security scans before review; QA is a mix of automated unit/integration tests and manual or smoke tests for critical flows. Releases follow a checklist (staging verification, rollback plan, release notes) and an incident/rollback playbook to minimize production risk.

## Roles & Communication

Roles are explicit — Project Manager (delivery coordination, schedules, risks), Product Manager (outcomes, prioritization), Developers (implementation, tests, reviews), QA (validation), and Stakeholders (approvals and inputs). Communication cadence includes daily standups, weekly delivery syncs, PM+PdM weekly alignment, demos at the end of sprints, and monthly stakeholder updates. Risks are tracked in a Risk Register and escalated via defined paths when necessary.
